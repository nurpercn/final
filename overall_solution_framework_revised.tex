\subsection{Overall Solution Framework}
\label{subsec:framework}

The method is built around a simple observation: sample sizes and
chamber settings cannot be chosen independently.
Increasing the number of samples of a product creates one additional
pull-down operation for each extra unit, so the upstream workload
grows.
At the same time, extra samples allow later tests to run in parallel,
which can reduce completion times when due dates are tight.
Which of these two effects dominates depends on how chamber capacity
is currently allocated across environments.
The search therefore alternates between assigning chambers to a given
sample vector and improving that sample vector under a fixed
assignment.
Algorithm~\ref{alg:framework} records this outer coordination;
the inner procedures are developed in the following subsections.

\begin{algorithm}[H]
\caption{Overall Solution Framework}
\label{alg:framework}
\begin{algorithmic}[1]
\State \textbf{Input:} instance data
\State \textbf{Output:} \((\mathbf{x}_{inc},\mathbf{s}_{inc},\Pi_{inc},T^{tot}_{inc})\)
\State Set \(s_p\leftarrow s_{\min}\) for all \(p\in\mathcal{P}\); \(\mathbf{s}\leftarrow(s_p)_{p\in\mathcal{P}}\) \label{step:fw-init}
\State Initialize the incumbent with \(T^{tot}_{inc}=+\infty\)
\For{\(i\leftarrow 1\) to \(I_{\max}\)}
    \State \(\mathbf{x}\leftarrow\) \Call{ChamberAssignment}{\(\mathbf{s}\)} \label{step:fw-assign}
    \State \((\mathbf{s}_{cand},\Pi_{cand},T^{tot}_{cand})\leftarrow\) \Call{SampleLocalSearch}{\(\mathbf{x},\mathbf{s}\)} \label{step:fw-ls}
    \If{the candidate improves the incumbent} \label{step:fw-lex}
        \State \((\mathbf{x}_{inc},\mathbf{s}_{inc},\Pi_{inc},T^{tot}_{inc})\leftarrow(\mathbf{x},\mathbf{s}_{cand},\Pi_{cand},T^{tot}_{cand})\)
        \State \(\mathbf{s}\leftarrow\mathbf{s}_{cand}\)
    \Else
        \State \((\mathbf{s}_{cand},\Pi_{cand},T^{tot}_{cand})\leftarrow\) \Call{VNS}{\(\mathbf{x},\mathbf{s}_{inc},\Pi_{inc},T^{tot}_{inc}\)} \label{step:fw-vns}
        \If{the VNS candidate improves the incumbent}
            \State \((\mathbf{x}_{inc},\mathbf{s}_{inc},\Pi_{inc},T^{tot}_{inc})\leftarrow(\mathbf{x},\mathbf{s}_{cand},\Pi_{cand},T^{tot}_{cand})\)
            \State \(\mathbf{s}\leftarrow\mathbf{s}_{cand}\)
        \Else
            \State \Return \((\mathbf{x}_{inc},\mathbf{s}_{inc},\Pi_{inc},T^{tot}_{inc})\) \label{step:fw-stop}
        \EndIf
    \EndIf
\EndFor
\State \Return \((\mathbf{x}_{inc},\mathbf{s}_{inc},\Pi_{inc},T^{tot}_{inc})\)
\end{algorithmic}
\end{algorithm}

We start from the minimum feasible sample count for every product
(Step~\ref{step:fw-init}).
At each outer iteration the chambers are first assigned so that the
available station capacity follows the environment-wise workload
implied by the current samples (Step~\ref{step:fw-assign}).
Sample sizes are then adjusted by local search
(Step~\ref{step:fw-ls}).
Every candidate is evaluated by constructing a feasible schedule with
an earliest-due-date (EDD) rule and reading off the resulting total
tardiness.
As already stated in the problem definition, a candidate replaces the
incumbent only if it reduces total tardiness, or if tardiness is
unchanged and fewer samples are used (Step~\ref{step:fw-lex}).
When local search cannot improve the incumbent, the sample vector is
perturbed by variable neighborhood search (VNS) and the same local
search is applied again (Step~\ref{step:fw-vns}).
After any accepted change the procedure returns to chamber
assignment, because the workload shares that justified the previous
assignment are no longer valid.
The search stops when VNS also fails to improve the incumbent
(Step~\ref{step:fw-stop}), or when a prescribed iteration limit is
reached.
